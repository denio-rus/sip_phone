# Доведение sip_phone до строгого RFC 3261 — спецификация правок

Дата: 2026-11-03. Статус: согласована, работы начинаются раньше АТС (`sip_pbx`).
Контекст: телефон правился под промышленный ECSS-10 и близок к стандарту, но
аудит кода (стек, парсер, work_log) выявил одно прямое нарушение и набор
упрощений. Цель — убрать отклонения, чтобы sip_phone использовался в автотестах
сигнальной части АТС как эталонно-совместимый клиент.

## Что исправляется

### 1. Магический cookie в клиентских Via-branch (нарушение)

RFC 3261 §8.1.1.7: branch нового клиентского запроса обязан начинаться с
`z9hG4bK`. `hangup_active` (`lib/sip_phone/sip/stack.ex:666`) шлёт
`branch=bye-<hex>` без cookie — ECSS проглатывает, строгий сервер вправе
отвергнуть. Все прочие branch генерируются правильно (`new_branch/0`).
Фикс: `put_via("bye-" <> rand_hex(6))` → `put_via(new_branch())`.

### 2. Честные таймеры транзакций §17 (отклонение)

Нынешняя лестница ретранслятов самодеятельна: старт с 2·T1 вместо T1
(`@t1_ms * 2 * retries_factor`), потолок 16·T1=8 с вместо T2=4 с для non-INVITE,
общий timeout ~3 мин вместо Timer B/F = 64·T1 = 32 с; ретранслят финального
ответа на INVITE с фиксированным шагом 1 с вместо экспоненциального Timer G.
Фикс: константы и порядок шагов §17.1.1/§17.1.2/§17.2.1 (T1=500 мс, T2=4 с,
64·T1), значения — из Application env (тесты гоняют с T1=20 мс).
Структурно упрощённые транзакции (без Timer D/H/I/J) сохраняются — это
задекларированное упрощение «Известные упрощения» work_log, не отклонение.

### 3. Record-Route / route set (отсутствие, станет обязательным с АТС)

UAC обязан использовать route set из 2xx (§12.1.2): in-dialog запросы
(BYE/ACK/UPDATE-нет) слать в первый Route, а не прямо в Contact — иначе
in-dialog сообщения обходят АТС и её трассировка слепнет. Сейчас `dialog_target`
(«stack.ex») всегда Contact собеседника. Фикс: сохранять Route-заголовки 200 OK
(на BOTH сторонах исходящего и входящего INVITE), приоритет route set над Contact.

### 4. 423 Interval Too Brief (отсутствие)

На `423` с `Min-Expires: N` — повтор REGISTER с `max(N, запрошенный)` (§24.15).
Сейчас 423 трактуется как любой ≥300 — «регистрация не удалась».
Заодно переносит в тестируемое поле ECSS-поведение («Interval Too Brief»
наблюдался живьём, work_log §6).

### 5. Поборки (в тех же файлах)

- `without_contact/1` — identity-заглушка (`stack.ex:1010`), удалить вместе с вызовами.
- `server_target`/`sip_uri_hostport`: мёртвые ветки `tap(fn _ -> state end)` и
  безразличный `port` — упростить без изменения поведения.

## Не будет сделано

RTP/медиa; TCP/TLS; PRACK/100rel; полноценные detached-стейты транзакций
(Timer D/H/I/J) — остаются задекларированными упрощениями; обработка line
folding (§7.2 obsolete); несколько одновременных вызовов.

## Порядок и проверки

Порядок: 1 → 2 → 3 → 4 → 5, каждый шаг — отдельный коммит с тестом
(док-правки — в том же коммите, правило CLAUDE.md).

Чем закреплено:
- `test/integration_test.exs` — fake-сервер получает корректные branch (проверка
  префикса `z9hG4bK` у BYE), таймеры из env (T1=20 мс: таймаут-тесты не виснут),
  сценарий 423 → повтор с Min-Expires; сценарий INVITE с Record-Route: 200 OK
  с Route → BYE уходит в Route-адрес fake-сервера, не в Contact.
- Существующие 10 doctests + 20 тестов остаются зелёными (ожидания fake-сервера
  обновляются только там, где менялся контракт).
- `mix format --check-formatted`, `mix credo --strict`,
  `ERL_LIBS=/opt/erlang-27/lib/erlang/lib mix dialyzer` — ноль замечаний.
- При доступности боевого ECSS-10 (10.107.1.124): регистрация/звонок/отбой
  ещё раз вручную; результат — строкой в work_log.
- Новая секция 22 в `work_log.md` («запрос → причина → фикс → чем закреплено»),
  синхронизация README/CLAUDE.md (изменение «Известных упрощений»).
