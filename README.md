# SIP-телефон с веб-интерфейсом

SIP UA (REGISTER + digest auth, INVITE/ACK/CANCEL/BYE) на Elixir/OTP 27.
Веб-интерфейс — на порту **8212**. Звук не передаётся (только сигнализация,
SDP с `a=inactive` / порт 9).

## Запуск (одной командой)

```bash
./run.sh
```

или вручную:

```bash
mix deps.get
mix run --no-halt
```

После запуска открыть <http://localhost:8212>.

Переменные окружения (необязательно):

| Переменная             | Значение по умолчанию | Назначение                      |
|------------------------|-----------------------|---------------------------------|
| `SIP_PHONE_WEB_PORT`   | `8212`                | порт веб-интерфейса             |
| `SIP_PHONE_SIP_PORT`   | `5080`                | локальный UDP-порт SIP-телефона |

Значения по умолчанию задаёт `config/config.exs`; в тестовом окружении
(`MIX_ENV=test`) они свои (`config/test.exs`: UDP **5180**, TCP **8312**) —
чтобы `mix test` мог работать параллельно с запущенным `./run.sh`.

## Как пользоваться

1. Ввести **адрес SIP-сервера** (`host[:port]`, порт по умолчанию 5060),
   **номер** и **пароль** → «Зарегистрировать». Статус покажет
   `регистрация…` → `успешно` или `ошибка: <причина>`.
2. «Позвонить» — исходящий вызов; во время звонка доступна кнопка «Отменить».
3. При входящем вызове появляются «Ответить» и «Отклонить»;
   во время разговора — «Положить трубку».
4. Кнопка **«Открыть лог SIP»** — отдельное окно (`/log`) с пошаговым ходом
   текущей операции: каждое отправленное (→) и полученное (←) SIP-сообщение,
   клик по строке раскрывает исходный текст сообщения.
5. Кнопка **«Проводник»** — раскрывает в основном окне секцию с деревом файлов
   проекта: каталоги раскрываются по клику, клик по файлу показывает рядом
   панель превью (текст до 256 КБ; для бинарных файлов — только размер).
   Корень дерева — каталог, содержащий приложение (видны документы проекта и
   `sip_phone/`), за его пределы выйти нельзя. Из скрытых (с точки) папок
   показывается только `.claude`, остальные скрытые записи не видны.
6. Ссылка **«документация»** в подвале главной — страница `/docs`: чтение
   HTML-документации (сгенерированной `mix docs`) и ссылки скачать её же в
   epub / markdown / txt. Без сгенерированного `doc/` страница подскажет команду.
7. Переключатель тёмной/светлой темы — внизу страницы (сохраняется в браузере,
   синхронизируется с окном лога).

## Архитектура

```
config/                     — порты по умолчанию (config.exs — боевые, test.exs — тестовые)
lib/sip_phone/
  application.ex          — супервизор: PubSub, LogBuffer, Stack, HTTP-сервер (Cowboy, 8212)
  pubsub.ex               — примитивный pub/sub на Registry (единственный топик "events")
  sip/message.ex          — парсер/билдер SIP-сообщений
  sip/stack.ex            — UAC/UAS стейт-машина: REGISTER+digest, INVITE/ACK/CANCEL/BYE,
                            ретрансляции UDP-транзакций, re-REGISTER по Expires
  sip/log_buffer.ex       — кольцевой буфер сообщений (ETS) для истории в окне лога
  web/router.ex           — REST API (/api/register, /api/call, /api/fs, …), статика, /ws, /docs
  web/ws.ex               — WebSocket: live-лог и состояние телефона
  web/file_browser.ex     — read-only обзор файлов проекта для секции «Проводник»
priv/static/              — index.html, log.html, docs.html, app.js, log.js, style.css
test/sip_phone_test.exs   — doctest'ы публичного API (парсер SipPhone.SIP.Message)
test/file_browser_tree_test.exs — дерево «Проводника»: видимость записей (фикстура в tmp)
test/integration_test.exs — интеграционные тесты с fake-SIP-сервером
```

Состояния телефона: `unregistered / registering / registered / failed`
(регистрация) и `idle / calling / incoming / active` (линия).

## Тесты

```bash
mix test
mix credo --strict                                     # стиль (конфиг .credo.exs, lib/)
ERL_LIBS=/opt/erlang-27/lib/erlang/lib mix dialyzer   # статические типы (см. CLAUDE.md: на системном OTP нет dialyzer)
```

Состав: 10 doctest'ов публичного API (парсер/билдер `SipPhone.SIP.Message`,
раскрытие компактных имён заголовков — тоже) и 20 тестов — 1 юнит + 10
файлового дерева «Проводника» + 9 интеграционных. Тесты дерева собирают
временное дерево в tmp и проверяют видимость записей: из скрытых (dot-)
показывается только каталог `.claude`, прочие скрытые папки и файлы скрыты.
Интеграционные сценарии: регистрация 401→digest→200, исходящий вызов и разговор,
завершение BYE, входящий вызов + ответ + BYE от абонента, отклонение (486),
отмена (CANCEL), доступность веб-интерфейса, проводник (список каталога,
превью файла, запрет выхода за корень проекта), документация (ссылка на
главной, `/docs`, раздача сгенерированных файлов). Тесты поднимают приложение
на тестовых портах и не конфликтуют с запущенным `./run.sh`.

## Документация

```bash
mix docs    # HTML-документация из @moduledoc/@doc (ex_doc, dev-only) → doc/index.html
```

Сгенерированное читается в веб-интерфейсе: страница `/docs` (ссылка
«документация» в подвале главной) показывает HTML-доки и даёт скачать их же
в epub (`sip_phone.epub`), markdown (`api-reference.md`, `readme.md`) и txt
(`llms.txt`). Роут работает без перезапуска после перегенерации `doc/`.
